## Задание 1. Подключение инструментов и библиотек OpenTelemetry и настройка трассировки приложения

В ходе выполнения задания было создано Flask-приложение, настроена его инструментация с помощью OpenTelemetry и организован сбор трассировок в Jaeger.

### Код приложения (app.py)
```python
from flask import Flask
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.instrumentation.flask import FlaskInstrumentor

# 1. Настраиваем провайдер трассировки
provider = TracerProvider()
trace.set_tracer_provider(provider)

# 2. Настраиваем экспортер (отправляем в Jaeger по gRPC)
otlp_exporter = OTLPSpanExporter(endpoint="http://jaeger:4317", insecure=True)
provider.add_span_processor(BatchSpanProcessor(otlp_exporter))

# 3. Инициализируем Flask и подключаем инструментацию
app = Flask(__name__)
FlaskInstrumentor().instrument_app(app)

@app.route("/")
def hello():
    return "Hello, OpenTelemetry and Jaeger!\n"

@app.route("/health")
def health():
    return "OK\n"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

## Ответы на контрольные вопросы

**1. Что такое OpenTelemetry? Атрибуты, события, контекст, журналы, трассировки, показатели?**
OpenTelemetry (OTel) — это открытая платформа для сбора телеметрии (метрик, логов, трассировок). Это стандарт индустрии.
- **Атрибуты (Attributes):** пары "ключ-значение", добавляемые к спанам, метрикам или логам для контекста.
- **События (Events):** точки во времени внутри спана (например, исключение или нажатие кнопки).
- **Контекст (Context):** объект, который передается между сервисами (через заголовки HTTP) для связывания спанов в одну трассировку.
- **Журналы (Logs):** текстовые записи о событиях в системе.
- **Трассировки (Traces):** дерево спанов, показывающее путь запроса через распределенную систему.
- **Показатели (Metrics):** числовые измерения (например, количество запросов, использование CPU).

**2. Что такое наблюдаемость? Надежность и показатели?**
Наблюдаемость (Observability) — это способность системы отвечать на вопросы о своем внутреннем состоянии на основе внешних данных (MLT). Надежность (Reliability) — это способность системы работать без сбоев. Показатели (SLO/SLI) — это метрики, которые измеряют уровень надежности (например, процент успешных запросов).

**3. Что такое трассировка? Что такое распределенная трассировка? Как собирать распределенную трассировку и какие проблемы имеются в распределенной архитектуре?**
Трассировка — это запись пути выполнения программы. Распределенная трассировка отслеживает запрос, который проходит через несколько сервисов. Собирается с помощью заголовков контекста (например, W3C Trace Context), которые передаются между сервисами. Проблема: сложность синхронизации времени, высокая нагрузка на сеть и необходимость единого стандарта.

**4. Сигналы OpenTelemetry: трассировки, метрики, логи?**
В OpenTelemetry три основных сигнала:
- **Traces** (Трассировки) — путь запроса.
- **Metrics** (Метрики) — агрегированные числовые данные.
- **Logs** (Логи) — структурированные записи событий.

**5. Инструменты OpenTelemetry: автоматические, ручные, библиотеки?**
- **Автоматические (Auto-instrumentation):** инструментация без изменения кода (через агенты или библиотеки, как `FlaskInstrumentor`).
- **Ручные (Manual):** добавление кода для создания спанов (через API).
- **Библиотеки (SDK):** наборы инструментов для конкретных языков (Python, Java и др.).

**6. Компоненты OpenTelemetry: спецификация, сборщики, библиотеки инструментальных средств, экспортеры, автоматические измерительные инструменты?**
- **Спецификация (Specification):** стандарты API и протоколов.
- **Сборщики (Collector):** прокси, который принимает, обрабатывает и экспортирует данные.
- **Библиотеки (Libraries):** SDK для генерации данных.
- **Экспортеры (Exporters):** отправляют данные в бэкенды (Jaeger, Prometheus).
- **Автоматические инструменты (Auto-instrumentation):** готовые модули для популярных фреймворков.

**7. Ресурс OpenTelemetry (телеметрия)?**
Ресурс (Resource) — это описание сущности, которая генерирует телеметрию (например, имя сервиса, версия, хост). Он добавляется к каждому спану и метрике.

**8. Экспортеры OpenTelemetry?**
Экспортеры — это компоненты, которые отправляют собранные данные во внешние системы (например, `OTLPSpanExporter` для Jaeger, `PrometheusExporter` для метрик, `ConsoleSpanExporter` для вывода в консоль).

**9. Что такое Prometheus? Как работает Prometheus?**
Prometheus — это система мониторинга и база данных временных рядов. Работает по модели pull (сам опрашивает эндпоинты `/metrics` приложений) и хранит данные локально.

**10. Концепции Prometheus?**
- **Метрика (Metric):** имя + набор меток.
- **Метка (Label):** пары ключ-значение для фильтрации.
- **Сэмпл (Sample):** значение метрики в конкретный момент времени.
- **Job/Instance:** цель опроса (сервис).

**11. Типы метрик?**
В Prometheus четыре типа:
- **Counter** (счетчик): только увеличивается.
- **Gauge** (датчик): может увеличиваться и уменьшаться (например, температура).
- **Histogram** (гистограмма): распределение значений (например, время ответа).
- **Summary** (сводка): похожа на гистограмму, но считает квантили на клиенте.

**12. Запрос и преобразование данных Grafana?**
Grafana использует язык запросов PromQL (для Prometheus) или LogQL (для Loki) для выборки и агрегации данных. Преобразования (Transformations) позволяют менять структуру данных (например, объединять таблицы, фильтровать, переименовывать поля).

**13. Источники данных Grafana?**
Grafana поддерживает множество источников: Prometheus, Loki, Jaeger, Elasticsearch, PostgreSQL, MySQL, InfluxDB и другие.

**14. Панели мониторинга Grafana?**
Панели (Panels) — это визуальные элементы (графики, таблицы, тепловые карты), которые отображают данные. Дашборд (Dashboard) — это набор панелей.

**15. Процесс обработки журналов Grafana Loki?**
Loki собирает логи через Promtail (агент), индексирует только метаданные (метки), а сами логи сжимает и хранит в объектном хранилище. Это делает его легковесным и быстрым.

**16. Варианты сборки журналов для Grafana Loki?**
- **Promtail:** стандартный агент для сбора логов с файлов.
- **Grafana Alloy:** новый агент (замена Promtail), поддерживающий OpenTelemetry.
- **Docker Driver:** плагин для сбора логов из контейнеров.
- **Fluentd/Fluent Bit:** через плагин Loki.
